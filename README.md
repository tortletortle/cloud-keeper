# 云朵饲养员 · 小小天空牧场

当前工程基线：**V0.12 → V0.12.1 工程化改造**。

本仓库以 2026-11-23 的 `CloudRanch_V0.12.html` 为功能基线。此次改造的目标是拆分工程、保护玩家存档、建立可重复测试与构建流程；不改变游戏的核心视觉方向，也不扩展新的生态玩法。

> 项目仍处于私有开发阶段。美术资产来源与授权尚未完成逐项核验，因此暂不添加开源许可证，也不应在确认授权前公开仓库或对外分发美术资产。

## 运行

需要 Node.js 20 或更高版本（仅用于测试和构建）。游戏运行本身不依赖第三方 JavaScript 包。

```bash
npm install
npm run verify
python -m http.server 8000
```

浏览器打开 `http://localhost:8000`。

也可以直接打开 `index.html`。使用本地 HTTP 服务更接近正式部署环境。

```text

  app.js                DOM、输入、渲染与运行时编排
  assets.js             美术资源清单（CloudKeeper 命名空间）

```

## 开发命令

- `npm test`：运行纯逻辑与存档测试。
- `npm run check`：检查 JavaScript 语法。
- `npm run build`：生成 `dist/` 并核对入口、资源引用。
- `npm run verify`：执行语法检查、测试和构建。

## 存档与兼容性

- 继续使用原存档键 `cloud-ranch-v01` 和数据版本 `1`，避免无必要地切断 V0.12 玩家存档。
- 缺失的旧字段会被归一化；非法云朵记录会被跳过，合法记录继续恢复。
- 重复或无法判定身份的云朵 ID 会明确拒绝自动覆盖，避免关系映射错乱。
- 无法读取的原始存档不会被静默覆盖；显式替换时先保留 `-unreadable-backup` 备份。
- 玩家仍可通过设置导入和导出 JSON 存档。

## 质量门槛

任何功能只有在对应自动化测试通过、构建成功，并完成必要的浏览器验收后，才可以标记为已验收。Node 单元测试通过不等于真实浏览器或移动设备验收通过。

## 项目规则

- 不直接向 `main` 推送未验证改动。
- 每个功能分支必须基于记录的共同基线，并保留可审查的变更。
- 不删除旧存档、不覆盖无法读取的原始数据。
- 不把尚未核实来源的美术素材声明为可自由使用。
