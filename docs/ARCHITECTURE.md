# 当前工程结构（V0.12.1）

## 目标

本轮仅建立可维护的模块边界，不把游戏重写成新引擎。现有玩法状态、视觉素材和主要交互以 V0.12 为行为基线。

## 模块职责

| 模块 | 职责 | 允许依赖 |
|---|---|---|
| CloudBrain | 性格参数、情绪判断、行为决策、代谢 | 纯数据 |
| CloudSocial | 关系归一化、社交提议、回应与关系变化 | 纯数据、传入 traits |
| CloudEcology | 天气、成长、育云、昼夜日数规则 | 纯数据、传入 spawn/spot |
| CloudSaves | JSON 解析、字段归一化、存档完整性与写入 | 传入类型、生态和关系规则 |
| app.js | DOM、交互、渲染、调度和模块编排 | 上述模块与浏览器 API |
| styles.css | 页面、场景和动画表现 | 无 JavaScript 依赖 |

## 数据流

1. 启动时由 `CloudSaves` 读取并校验本地 JSON。
2. `CloudBrain`、`CloudSocial` 和 `CloudEcology` 只处理数据，不直接读写 DOM。
3. `app.js` 将模拟状态投影到 DOM，并接收用户输入；静态资源路径变化时才更新 DOM 属性，弹簧积分不再为每个子步创建临时数组。
4. 存档写入统一经过 `CloudSaves.write`。

## 时间模型

- 模拟时间只在牧场运行且页面可见时推进。
- 打开弹窗时停止模拟循环，关闭后恢复。
- 尊重 `prefers-reduced-motion`：减少动态效果时跳过弹簧物理的逐帧积分与 CSS 变量写入。
- 页面切到后台时保存当前状态；返回前台后重置帧间隔，避免把后台停留时间当成模拟时间。
- 牧场日数由累计模拟时间推导，不再由手动昼夜切换直接增加。当前 `DAY_LENGTH=180s`（4 个 45s 天气片段），这是为消除刷天漏洞设定的初始节奏参数，后续应由游戏平衡验证，而不是视为最终玩法定案。

## 错误边界

主循环捕获运行时异常并暂停模拟，向玩家显示明确状态，不允许异常直接终止整个 requestAnimationFrame 链后静默冻结。

## 暂未完成的架构研究

本文件描述当前落地的模块边界，不代表最终架构设计已经定稿。事件总线、渲染适配层、配置/平衡参数、模拟时钟注入、长期记忆模型和 B 阶段生态扩展接口，需要在本轮核心工程改造完成后单独评估，不在本次擅自实现。
